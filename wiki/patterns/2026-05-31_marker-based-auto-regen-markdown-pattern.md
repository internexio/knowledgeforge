# Marker-based auto-regen pattern for hand-curated markdown

## Problem

A pipeline produces both machine-computed status (verdicts, counts, tables) AND human-curated narrative (interpretation, recommendations, context) for the same artifact. Two failure modes emerge:

1. **Fully-auto:** The script regenerates the whole file every run and overwrites any narrative the human added. Authors stop trusting the file because their work disappears.
2. **Fully-manual:** The script writes a separate machine-readable file, the human copy-pastes data into a hand-curated file. Data goes stale immediately; the two files diverge silently.

The right pattern is a **single canonical file** with a script-replaceable section inside a hand-curated wrapper.

## Pattern

Mark the auto-regenerated region with HTML comment markers:

```markdown
<!-- AUTO:SECTION_NAME-BEGIN — regenerated by scripts/X.py; do not edit between markers -->
## Auto-computed status

(content the script writes)
<!-- AUTO:SECTION_NAME-END -->

## Curated narrative

(content the human writes — script never touches)
```

The regeneration function:

```python
def _update_section(path, marker_name: str, auto_content: str) -> None:
    BEGIN = f"<!-- AUTO:{marker_name}-BEGIN — regenerated by ...; do not edit between markers -->"
    END = f"<!-- AUTO:{marker_name}-END -->"
    new_block = f"{BEGIN}\n{auto_content}\n{END}"

    if path.exists():
        text = path.read_text(encoding="utf-8")
        if BEGIN in text and END in text:
            before, _, rest = text.partition(BEGIN)
            _, _, after = rest.partition(END)
            text = before + new_block + after
        else:
            # Markers absent (manually-written file predates this convention)
            # — insert the block after the first H1 so narrative is untouched.
            lines = text.splitlines(keepends=True)
            insert_at = 1 if lines and lines[0].startswith("# ") else 0
            text = "".join(lines[:insert_at]) + "\n" + new_block + "\n\n" + "".join(lines[insert_at:])
        path.write_text(text, encoding="utf-8")
    else:
        # First-run bootstrap: write a minimal skeleton with markers + placeholder
        skeleton = (
            "# <Document Title>\n\n"
            f"{new_block}\n\n"
            "## Narrative\n\n"
            "_Fill in the curated narrative here. The auto block above is "
            "regenerated on each run of the producing script._\n"
        )
        path.write_text(skeleton, encoding="utf-8")
```

## Properties

- **Idempotent.** Running the regenerator twice in a row produces no diff.
- **Narrative-preserving.** Sections outside the markers are byte-identical across runs.
- **Bootstrap-safe.** First run on a fresh project produces a usable file with a clear "fill in narrative" placeholder; humans don't have to know the convention to start.
- **Self-documenting.** The BEGIN marker's "regenerated by X; do not edit" inline comment tells humans where the boundary lives.
- **Backwards-compatible.** Files predating the convention (no markers present) get the block inserted after the first H1; narrative below is preserved. Subsequent runs use surgical marker-based replacement.

## When to Use

- Pipeline produces a per-run status digest the team needs to act on AND a human-written interpretation the team needs to read alongside it.
- Multiple instances of the same artifact (per-account reports, per-customer digests) where the curated narrative differs per instance but the data block is uniform.
- Specs call for a single named output ("aggregate.md", "summary.md") but the file needs both auto + curated parts.
- Revision control stores both the auto-generated data and the human narrative in one place, and you want the history to be readable.

## When NOT to Use

- Pure machine-readable artifacts (JSON / YAML / CSV) — markers add noise; use a separate file or a frontmatter block.
- Pure narrative artifacts (essays, decision logs) — no auto regen needed; the pattern adds friction.
- Files with rapid auto-regen cycles (per-commit, per-CI-run) where a human is unlikely to want to interleave narrative — use a separate generated file.
- When the auto-region needs to be deeply interleaved with narrative — markers enforce a contiguous span. If the auto-content fragments belong in 5 different places in the doc, this pattern fights you.

## Comparison to Related Patterns

### vs. Markdown-to-Binary Drift
The [[markdown-binary-artifact-drift-independent-editing]] entry addresses keeping separate markdown and binary files in sync. This pattern solves the harder case: a **single markdown file** that must hold both auto and curated content without separate regeneration tooling (Marp, Pandoc, etc.).

### vs. Multi-producer JSONL Markers
The [[schema-marker-multi-producer-jsonl-contract]] entry uses schema markers (e.g. `kind` field) to discriminate row types in a shared append-only file. This pattern uses **structural markers** (comment blocks) inside a single markdown document to delimit regenerated vs. hand-edited regions. The mechanism is different (JSONL field vs. HTML comments) and the use case is different (multi-producer queue vs. single-pipeline with curated narrative).

## Grounding

Implemented 2026-05-31 in `~/Scripts/[project]/scripts/phase_0b_correlate.py` (`_update_aggregate_section`), verified by:

1. First run on a freshly-written `aggregate.md` (with markers + curated narrative): meta-verdict block populated, narrative byte-identical.
2. Second run with no data changes: file diff empty (idempotent).
3. Verified preservation of 5 curated H2 sections (`Headline`, `Wedge check`, `Confounds`, `Recommendation`, `Resolves`) across runs.

The pattern resolved a spec-drift situation where the harness had grown TWO aggregate-class files (one script-generated, one hand-written) because there was no clean way to combine them. Consolidating to a single marker-managed aggregate.md matched the spec's named output without losing either the machine-computed verdict or the curated decision narrative.
