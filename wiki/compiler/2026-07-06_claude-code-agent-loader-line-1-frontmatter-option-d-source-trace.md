# Claude Code Agent Loader Silently Rejects Any File With Content Before Line-1 `---`

## Symptom

`~/.claude/agents/<mode>.md` files that do NOT have `---` as the literal first three bytes are silently omitted from agent discovery. `claude --agent <mode>` returns rc=1 with `--agent '<mode>' not found. Available agents: ...` and the mode is missing from the "Available agents" list. No warning is emitted; there is no log to check. The file is treated as if it doesn't exist.

## Reproduction — Positive (Working Agent)

Verified 2026-07-06 against `~/.claude/agents/cos-*.md`, all present in discovery:

```
---
name: cos-analysis
description: ...
model: sonnet
tools: Read, Grep, Glob
---

# COS Analysis Mode
...
```

Line 1 is `---`. No BOM, no whitespace, no HTML comment.

## Reproduction — Negative (Broken Shape)

Broken shape produced by kf-compile between 2026-07-02 11:19 and 2026-07-06 (12 KF agents affected; [project] iteration_loop stage_1_critic dark for 4 nights):

```
---

**Sections:** [Protocol](#protocol) · ...

---
name: critic
description: ...
---

# Critic Mode
```

The loader parses the FIRST `---...---` block for frontmatter. Here it's empty (no `name:` field). The real frontmatter, nested inside a second `---...---`, is treated as body content. `name:` never resolves, so the mode never registers.

Prior form (also broken, resolved by commit 5981a7e — see kf-compile.py history):

```
<!-- Generated by kf-compile | source: ... | version: 7.15.0 -->
---
name: critic
...
```

Line 1 is the HTML comment, not `---`. Same silent rejection.

## The Rule

Line 1 of any `~/.claude/agents/*.md` MUST be the literal three bytes `---\n`. Not `---` with trailing whitespace on the same line, not preceded by a BOM, not preceded by an HTML comment. The Claude Code agent discovery parser reads line 1 as the YAML frontmatter delimiter and any deviation causes silent skip.

## Where Trace Comments CAN Live — Option D

An HTML comment placed AFTER the closing `---` of the frontmatter block is tolerated by the loader — it becomes body content that the loader ignores. This is the "Option D" pattern:

```
---
name: critic
description: ...
tools: Read, Grep, Glob
---
<!-- Generated by kf-compile | source: 07_critic_agent.md | version: 7.22.1 -->

**Sections:** [Protocol](#protocol) · ...

---

# Critic Mode
```

This shape preserves the loader constraint (`---` on line 1) AND keeps an in-file source-attribution trace visible when a human opens the compiled artifact. Verified 2026-07-06 (kf-compile 7.22.1); all 12 KF agents discover successfully with this shape.

## Where Trace CANNOT Live

- Line 1 (breaks loader — silent rejection).
- Inside the YAML frontmatter block as a `#` YAML comment: not tested this session; theoretically allowed by YAML spec, but any strict parser tooling downstream (validators, IDE previews) may warn. Option D is safer.
- Anywhere with a BOM before it (untested but flagged by convention).

## Grep Clues for Future-Me

When a KF agent goes missing from `claude --agent` discovery:

1. `head -1 ~/.claude/agents/<mode>.md` — is line 1 exactly `---`?
2. `hexdump -C ~/.claude/agents/<mode>.md | head -1` — is byte 0 the `-` character (0x2d), not a BOM (0xef 0xbb 0xbf)?
3. Compare shape against a working agent (`~/.claude/agents/cos-*.md` reliably work).

## When This Applies

Anyone generating agent `.md` files for Claude Code — kf-compile, plugin bundle tools, custom generators, or manual authoring.

## When This Does NOT Apply

- Skills (`~/.claude/skills/kf/*.md`) — skills use a different loader that tolerates leading HTML comments (kf-compile puts `<!-- Generated -->` on line 1 for skills).
- Docs (`~/.claude/docs/knowledgeforge/*.md`) — no frontmatter at all; leading HTML comment fine.
- Rules (`~/.claude/rules/*.md`) — different loader; not affected.
