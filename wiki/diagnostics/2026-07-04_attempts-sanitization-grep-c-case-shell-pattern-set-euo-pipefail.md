# $attempts sanitization for grep-c | case shell pattern under set -euo pipefail

## The failure mode

A watchdog script wedged sem-tools for **7 days** silently. Every launchd fire logged:

```
[2026-06-27 10:00:34] Backoff: attempt 0
0, waiting 7200s
```

Note the split: `attempt 0` on one line, `0, waiting 7200s` on the next. `log()` writes single-line entries — the split means `$attempts` contained a literal newline. The watchdog exited at the backoff check every cycle, never proceeded.

## Root cause

The pattern (used in ~46 per-repo happy-watchdog.sh scripts generated by a template):

```bash
if [[ -f "$BACKOFF_FILE" ]]; then
    attempts=$(grep -c "^fail:" "$BACKOFF_FILE" 2>/dev/null || echo 0)
    ...
    case $attempts in
        [12])   wait=60 ;;
        3)      wait=300 ;;
        ...
        *)      wait=7200 ;;
    esac
    if (( now - last_fail < wait )); then
        log "Backoff: attempt $attempts, waiting ${wait}s"
        exit 0
    fi
fi
```

Two things conspire:

1. **`grep -c` output isn't guaranteed to be a bare int under corrupt-file conditions.** With `set -euo pipefail`, a `grep -c` on a partial-write or non-ASCII backoff file can succeed while emitting content that isn't `\d+\n`. The `|| echo 0` fallback only fires on grep exit-code 1 (no matches); it doesn't sanitize output on exit-code 0.
2. **`case $variable in`'s `*)` fallthrough silently applies the last-defined branch value.** When `$attempts` contains a non-`[12345678]` value (e.g., `"0\n0"`), the case statement matches `*)` and sets `wait=7200`. No error, no warning — just a 2-hour lockout that resets every launchd fire.

The combination means: **corrupt backoff file → non-int `$attempts` → 2-hour lockout, forever, no visible error**. Under `set -euo pipefail` the pipe/`|| echo 0` masks the failure surface completely.

## The fix (two lines)

Immediately after any `attempts=$(grep -c ...)`, `count=$(wc -l ...)`, `n=$(some_cmd | head -1)`:

```bash
attempts=$(grep -c "^fail:" "$BACKOFF_FILE" 2>/dev/null || echo 0)
# Force bare int — grep -c can under corrupt-file edge cases return
# non-int values that wedge the case fallthrough into the *) branch.
attempts=$(echo "$attempts" | head -1 | tr -cd "[:digit:]")
[[ -z "$attempts" ]] && attempts=0
```

Three defenses:
1. `head -1` — collapse to a single line if the value somehow got newlines.
2. `tr -cd "[:digit:]"` — strip everything that isn't a digit.
3. `[[ -z ]] && =0` — if the strip left nothing, default to 0 rather than empty string (empty string won't match `[12]` and will fall through to `*)`).

## When to apply

Anywhere you feed a "should be numeric" shell variable into:
- `case $var in [num]...)` — this session's failure mode
- Arithmetic comparison `(( var > N ))` — will exit non-zero under `set -e` on non-int
- Array indexing `${arr[$var]}` — silent wrong-index access

Especially urgent when the script:
- Runs under `set -euo pipefail` (masks the underlying error surface)
- Runs from launchd/cron (no interactive shell to spot the wedge)
- Has silent failure modes (like a watchdog that reports "success" when it just skipped everything)
